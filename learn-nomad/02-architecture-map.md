## Why the "Read now" set is the core path (not merely widely referenced)

The core path is a chain of ownership handoffs. Each "Read now" item is a *handoff point* where one owner stops and another starts, or where a durable state transition occurs:

1. **Agent wiring** — decides whether the HTTP layer talks to an in-process server or a remote one; without it "who is the leader" is confusing in `-dev` mode.
2. **HTTP API** — public contract → internal structs; first place namespace and token are attached.
3. **RPC plumbing** — the only place non-leaders become leaders (`forward`) and the only place writes become Raft entries (`raftApply`).
4. **FSM + State store + structs** — the only place durable state changes; every later step reads from here.
5. **Job registration** — the *only* write path for desired state in the normal case.
6. **Eval broker + worker** — converts a durable write into scheduler work with ordering guarantees and retry.
7. **Scheduler** — the decision.
8. **Plan apply** — enforcement of the decision under concurrency.
9. **Node endpoint + heartbeat** — liveness input to the decision and the failure-detection trigger.
10. **Client + alloc runner + task runner** — the only place processes start, and the source of observed state.

Everything in "Read soon" (deployments, drivers, client state DB, ACL, observability) modifies *how* the core path behaves but is not required to see a job become a process and a failure become a replacement.
